# NVR Viewer

เว็บดูกล้องวงจรปิดจาก NVR ผ่าน **RTSP** แบบ **วิดีโอสด** ภายในวงแลน
สร้างด้วย **FastAPI + ffmpeg (RTSP → HLS) + hls.js**

## คุณสมบัติ
- ดูหลายกล้องพร้อมกันเป็น grid (ปรับ 1–4 คอลัมน์)
- ใช้ `-c:v copy` ไม่ transcode → CPU ต่ำมาก รองรับทั้ง H.264 และ H.265
- เปิดสตรีม ffmpeg เมื่อมีคนดูเท่านั้น และปิดเองเมื่อไม่มีคนดูเกิน 30 วิ
- เครื่องไหนก็ตามในวงแลนเปิดเบราว์เซอร์เข้าดูได้

## ความต้องการ
- Python 3.10+
- `ffmpeg` (ตรวจ: `ffmpeg -version`)

## ติดตั้ง & ใช้งาน

```bash
./run.sh          # ครั้งแรกจะสร้าง venv + ติดตั้งให้อัตโนมัติ (พอร์ตเริ่มต้น 2318)
```

จากนั้นตั้งค่ากล้อง **ผ่านหน้าเว็บ** (ไม่ต้องแก้ไฟล์เอง):
1. เปิด `http://<ไอพีเครื่องนี้>:2318`
2. กด **⚙️ ตั้งค่ากล้อง**
3. กรอก **IP / ชื่อผู้ใช้ / รหัสผ่าน** เลือก **ยี่ห้อ** → ระบบสร้าง RTSP URL ให้เอง
4. กด **ทดสอบการเชื่อมต่อ** เพื่อเช็ค แล้วกด **บันทึก & ใช้งาน**
5. กลับไปหน้าแรก ดูภาพสดได้ทันที

> เปลี่ยนพอร์ต: `PORT=8080 ./run.sh`

## รูปแบบ RTSP URL ที่พบบ่อย
| ยี่ห้อ | ตัวอย่าง |
|--------|----------|
| Hikvision | `rtsp://admin:pass@192.168.1.64:554/Streaming/Channels/101` (101=ch1 main, 102=sub) |
| Dahua | `rtsp://admin:pass@192.168.1.108:554/cam/realmonitor?channel=1&subtype=0` |
| Uniview | `rtsp://admin:pass@192.168.1.50:554/media/video1` |
| ทั่วไป (ONVIF) | ลองดูจากหน้า config ของ NVR หรือใช้ ONVIF Device Manager หา URL |

> ช่อง **sub stream** (เช่น .../102, subtype=1) ความละเอียดต่ำกว่า เหมาะกับดูหลายกล้องพร้อมกันลื่นกว่า

## ONVIF (ดึง URL อัตโนมัติ + ค้นหากล้อง + PTZ)
แทนที่จะเดา RTSP path ตามยี่ห้อ ใช้ ONVIF ให้กล้องบอก URL เองได้:
1. หน้า **⚙️ ตั้งค่ากล้อง** → กด **🔍 ค้นหากล้อง ONVIF** เพื่อสแกนหากล้องในวงแลน (WS-Discovery) แล้วกด **+ เพิ่ม**
   — หรือกด **+ เพิ่มกล้อง** เองแล้วเลือกยี่ห้อ **ONVIF** กรอก IP/พอร์ต ONVIF (ปกติ 80)
2. กรอก **ชื่อผู้ใช้/รหัสผ่าน** แล้วกด **ดึงจาก ONVIF** → ระบบดึง RTSP, snapshot, รายการโปรไฟล์ และตรวจว่ารองรับ **PTZ** ให้อัตโนมัติ
3. เลือกโปรไฟล์ (main/sub) แล้วกด **บันทึก & ใช้งาน**
4. กล้องที่รองรับ PTZ จะมีปุ่มลูกศร/ซูม โผล่ที่มุมล่างขวาของภาพในหน้าดูกล้อง (กดค้างเพื่อเลื่อน)

> ต้อง **เปิด ONVIF** ในเมนูตั้งค่าของตัวกล้องก่อน (บางรุ่นปิดมาจากโรงงาน) และ ONVIF มักอยู่พอร์ต 80 — ถ้าสแกนไม่เจอให้กรอก IP/พอร์ตเองแล้วกด “ดึงจาก ONVIF”

### กล้อง XiongMai / Sofia (จีนทั่วไป — แอป XMeye, iCSee ฯลฯ)
กล้องกลุ่มนี้มักมีลักษณะเฉพาะ และต้องจัดการต่างจากยี่ห้อหลัก:
- **ONVIF ปิดมาจากโรงงาน** — ต้องเข้าไปเปิดในแอปกล้อง/เว็บของกล้องก่อน แล้วค่อยใช้ **🔍 ค้นหา / ดึงจาก ONVIF** (วิธีที่แนะนำ เพราะจะได้ RTSP path ที่ถูกต้องอัตโนมัติ ไม่ต้องเดา)
- **มี anti-brute-force** — ถ้ายิงทดสอบ RTSP ผิด path รัวๆ กล้องจะ **บล็อก IP เครื่องที่ทดสอบชั่วคราว** (เชื่อมต่อไม่ติด/ping ไม่ผ่าน) แก้โดย **เว้นสักพัก (~10 นาที) หรือรีสตาร์ทกล้อง** แล้วทดสอบ **ทีละ path** อย่ายิงพร้อมกันหลายอัน
- สังเกตได้จาก: เปิดเฉพาะพอร์ต 554 (+ พอร์ตแปลกๆ เช่น 5000), RTSP server โฆษณาเมธอด `USER_CMD_SET`
- ถ้าเปิด ONVIF ไม่ได้จริงๆ ให้หา RTSP path จากแอปกล้องโดยตรง แล้วใส่แบบ **custom**:
  `rtsp://admin:PASSWORD@IP:554/<path>`
- **path ที่พบบ่อยของกล้องกลุ่มนี้:** `/onvif1` (main) และ `/onvif2` (sub)
- **สำคัญ: บางรุ่นต้องใช้ transport = UDP** — ถ้าตั้งเป็น TCP จะขึ้น `Invalid data` ภาพไม่มา
  ในหน้าตั้งค่ามีช่อง **Transport** ให้เลือก ถ้ากล้องนิ่งๆ แต่ภาพไม่ขึ้นด้วย TCP ให้ลองสลับเป็น **UDP**
- main stream (H.265 บิตเรตสูง) บน UDP อาจมีแพ็กเก็ตหายจนภาพไม่ขึ้น — ใช้ **sub (`/onvif2`)** จะนิ่งกว่า
- **กล้องส่ง H.265 (HEVC)** เบราว์เซอร์ส่วนใหญ่ (Chrome/Firefox บน Windows/Linux) เล่น HEVC ผ่าน HLS ไม่ได้ (ภาพดำแต่ขึ้น LIVE) — ในหน้าตั้งค่าช่อง **วิดีโอ** ให้เลือก **“แปลงเป็น H.264”** ระบบจะ transcode ด้วย libx264 ให้เล่นได้ (แลกกับ CPU ที่สูงขึ้น)

## ทดสอบว่า RTSP ใช้ได้ก่อน
```bash
ffmpeg -rtsp_transport tcp -i "rtsp://admin:pass@192.168.1.64:554/Streaming/Channels/101" -t 3 -f null -
```
ถ้าคำสั่งนี้อ่านเฟรมได้ แปลว่าใส่ใน cameras.json แล้วเว็บจะแสดงได้

## ปรับแต่ง
- พอร์ต: `PORT=8080 ./run.sh`
- เวลา idle ก่อนปิดสตรีม / ความยาว segment: ดู `stream.py`

## ข้อควรรู้
- หน่วงเวลา (latency) ของ HLS ราว 2–5 วิ ตามปกติของโปรโตคอล
- ไฟล์ `cameras.json` มีรหัสผ่านกล้อง ถูก gitignore ไว้แล้ว — อย่า commit
- ออกแบบให้ใช้ภายในวงแลน ไม่ควรเปิดออกอินเทอร์เน็ตตรงๆ โดยไม่มี auth/reverse proxy

## Security

This app has no authentication and is meant for a trusted LAN. Do not expose it to the Internet; camera passwords live in `cameras.json` (git-ignored) — never commit it.
